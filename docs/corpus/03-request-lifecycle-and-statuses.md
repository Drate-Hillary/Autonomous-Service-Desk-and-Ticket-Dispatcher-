# Request Lifecycle and Statuses

*Sample knowledge-base article for the Resolv-HQ prototype. Synthetic, team-authored. Version 1.0.*

## 1. Creating a request
A customer creates a request with a title, a category, a description, and optional attachments. The more detail given, the faster it can be handled.

## 2. Statuses
A request moves through these statuses: New (received, not yet picked up), In progress (a support agent is working on it), Waiting on customer (the agent needs information from you), Resolved (a solution has been provided), Closed (confirmed complete), and Cancelled (withdrawn before completion).

## 3. Priority
Each request has a priority: low, medium, high, or critical. Priority is set by support staff and reflects impact and urgency.

## 4. Responding when waiting on customer
When a request is Waiting on customer, reply in the request messages. The request returns to In progress after you reply. A request left in this status for 7 days may be moved to Resolved.

## 5. Reopening
A Resolved request can be reopened by replying within 7 days. After a request is Closed, open a new request and refer to the old one.

## 6. Feedback
After a request is Resolved, customers can rate the support they received. Feedback is optional.
